# 广州服务器开发环境（guangzhou）

> **实测日期：2026-11-18。** 通过本地 SSH 配置中的 `guangzhou` 别名连接服务器，运行只读命令采集。以下为**这台服务器**的环境，不是 Windows 主机、WSL2 或 i.MX6ULL 开发板。未记录公网 IP、用户名、SSH 密钥、主机名及序列号。

## 1. 系统与硬件

| 项目 | 实测结果 |
| :--- | :--- |
| Linux 发行版 | Ubuntu 22.04 LTS |
| 内核 | `5.15.0-164-generic` |
| CPU 架构 | `x86_64` |
| CPU 型号（虚拟机所报告） | AMD EPYC 7K62 48-Core Processor |

## 4. 放到 40 周学习计划里，能承担什么？

- **目前可以开展：** W01 起的基础 C/C++ 编译、Makefile、Git、Python 脚本、`strace` 系统调用观察，以及不依赖外设的 Linux 用户态练习。
- **补齐必要工具后：** 可以在服务器上开展 GDB、CMake、部分内核模块编译和基础性能/跟踪实验；加载内核模块仍需测试权限、内核配置及运行环境限制。
- **应继续在真实开发板做：** i.MX6ULL 的设备树、GPIO、I2C、SPI、中断、寄存器与真实外设调试。广州服务器是 **x86_64 云端 Linux**，不能冒充 ARM 真机。
- **更适合本地电脑或资源更充裕的环境：** AArch64/QEMU、QEMU PCI EDU 和较重的交叉编译。该服务器仅 2 vCPU、约 2 GiB 内存，且没有 `/dev/kvm`，使用 QEMU 软件模拟可能很慢。

**本次没有安装软件，也没有修改服务器配置。** 不应据此认为已经完成 GDB、QEMU、内核模块加载或 GitHub 网络访问测试。

## 5. 后续按需补齐（建议命令，未执行）

基础调试和构建工具：

```bash
sudo apt update
sudo apt install gdb cmake ninja-build pkg-config
```

当学习进行到交叉编译阶段，再考虑：

```bash
sudo apt install gcc-aarch64-linux-gnu gcc-arm-linux-gnueabihf
```

> 真实 i.MX6ULL 内核模块应优先使用**与开发板当前镜像匹配**的厂商内核源码和工具链。服务器安装通用交叉编译器并不保证能直接构建板卡驱动。服务器网络是否能访问软件源与 GitHub，也需要单独验证。

## 6. 复核方法

在授权的 Windows 电脑上使用已有 SSH 配置中的别名连接：

```powershell
ssh guangzhou
```

本次使用的只读检测脚本：[probe_guangzhou_environment.sh](../09-维护与修订/probe_guangzhou_environment.sh)。

环境变化后可以重新探测，再手动更新此文档；**不要把 SSH 配置、密钥、服务器 IP 或访问令牌提交到公开仓库**。
