### 1. 【GCC 编译四步与笔记注释核对】
你在 `note.md` 的 D1 中写下了分步编译命令，并在 `code/w01/D1/` 下实际生成了 `hello.i`、`hello.s`、`hello.o` 和 `hello`：
```bash
gcc -E hello.c > hello.i   # 第 1 步
gcc -S hello.i             # 第 2 步 -> hello.s
gcc -c hello.s             # 第 3 步 -> hello.o
gcc hello.o -o hello       # 第 4 步 -> hello
```
你在笔记第 23 行给 `gcc -c hello.s` 写的注释是 `// 3. 链接 -> hello.o 目标文件`。请问把汇编文件 `hello.s` 转为目标文件 `hello.o` 的第 3 步，准确名称应该是什么？
- **A.** 预处理（Preprocess）
- **B.** 编译（Compile）
- **C.** 汇编（Assemble），第 4 步 `gcc hello.o -o hello` 才是链接（Link）
- **D.** 链接（Link）

**我的作答**：
 
<details><summary>💡 点击查看答案与解析</summary>

- **正确答案**：**C**
- **解析**：你在笔记第 16 行写的总流程 `C源文件-》预处理-》编译-》汇编-》链接-》可执行文件` 是完全正确的！只是第 23 行代码注释随手把第 3 步 `gcc -c hello.s` 写成了“链接”。`-c` 的作用是把汇编代码（`.s`）翻译成机器码目标文件（`.o`），这一步叫**汇编**；最后把 `.o` 和 C 标准库里的 `printf` 合在一起生成可执行文件 `hello` 才叫**链接**。
</details>

### 4. 【代码找茬：你写的 `code/w01/D1/helloTeste.c` 少做了哪一步？】
来看你在 `code/w01/D1/helloTeste.c` 第 8～16 行写的代码：
```c
	int * number = NULL;
	int testNum;
	number = malloc(sizeof(int));
	if(number ==NULL){
		return 0;
	}

	printf("hello world!!!\r\n");
	return 0;	
```
你做得很好的一点是：**初始化指针为 `NULL`，并且在 `malloc` 之后立刻检查了 `if (number == NULL)`**。
但对照你在笔记第 39 行写的“**指针问题，不能乱处理，要仔细考虑好为什么要这样做**”，这段代码在 `printf` 之后、`return 0;` 之前，漏掉了哪一句必须配对调用的函数？如果不写这一句，在一个长期循环运行的设备程序里会导致什么后果？

**我的作答**：

<details><summary>💡 点击查看答案与解析</summary>

- **答案要点**：
  1. 漏掉了 **`free(number);`**（释放完后还可以顺手写上 `number = NULL;` 防止悬垂指针）。
  2. 后果：会导致**内存泄漏（Memory Leak）**。在 `main` 马上退出的小程序里操作系统会替你兜底回收，但在你写的 `ScoliosisLinuxMachine` 或显微镜后台常驻进程里，每次调用漏释放 4 字节，跑几天内存就会耗尽被系统强杀（OOM）。
</details>
