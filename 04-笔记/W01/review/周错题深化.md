### 🔍 重点核查 E01：GCC 编译四步里，“汇编（`-c`）”和“链接”到底在干啥？

#### 1. 深入剖析与大白话讲解
你在 [note.md 第 16 行](../note.md#L16) 写的总路线 `C源文件 -> 预处理 -> 编译 -> 汇编 -> 链接 -> 可执行文件` 是完全对的，但第 23 行写代码注释时顺手写成了 `// 3. 链接 -> hello.o 目标文件`。为什么容易把这两步搞混？我们用你在 `code/w01/D1/` 里生成的真文件来对比：
- **第 3 步 `gcc -c hello.s`（汇编 Assemble → 生成 `hello.o`）**：
  - `hello.s` 是人还能看懂的英文汇编指令（比如 `call printf`）。
  - `gcc -c` 调用汇编器（`as`），把 `hello.s` 一行行翻译成 CPU 认识的二进制机器码，打包成 **`hello.o`（目标文件）**。
  - **关键点**：此时的 `hello.o` **还不能直接运行**！因为你在代码里调了 `printf`，但 `printf` 的实现代码在系统 C 标准库（`libc.so`）里，`hello.o` 里只留了个空位写着“我需要找 `printf`”。
- **第 4 步 `gcc hello.o -o hello`（链接 Link → 生成可执行文件 `hello`）**：
  - 链接器（`ld`）登场，把你的 `hello.o` 和系统 C 标准库“焊”在一起，把 `printf` 的真实地址填进空位里，最终生成能直接运行的 **`hello`**。

### 🔍 重点核查 E02：`malloc` 的生命周期与 `gcc -Wall` 零警告习惯

#### 1. 深入剖析与大白话讲解
在 [helloTeste.c](../../../code/w01/D1/helloTeste.c) 里，你写了 `number = malloc(sizeof(int));`，检查了 `if (number == NULL)`，但没有写 `free(number);`。
- **为什么在设备软件里这是高压线？**
  栈上的局部变量（比如 `int testNum;`）在函数 `{ ... }` 结束时会自动销毁；但 `malloc` 是在**堆（Heap）**上画了一块地，这块地的钥匙在指针 `number` 手里。如果函数结束前不调用 `free(number);`，局部变量 `number` 消失了（钥匙扔了），但堆上那 4 个字节永远显示“有人占着”，谁也用不了。
- **正确的一套组合拳**：
  ```c
  int *number = (int *)malloc(sizeof(int));
  if (number == NULL) {
      return -1; // 申请失败立刻退出
  }
  *number = 42;  // 正常使用这块内存
  free(number);  // 用完立刻归还给堆
  number = NULL; // 钥匙毁掉，防止后面误用变成悬垂指针（野指针）
  ```

### 🔍 重点核查 E03：8 位二进制 `1111 1110` 到底是 `254` 还是 `-2`？（彻底搞懂补码）

#### 1. 深入剖析与大白话讲解
你在 [note.md 第 113 行](../note.md#L113) 写了 `-254 -> 1111 1110`，紧接着又写了取反加 1 得到 `0000 0010`（十进制的 `2`）。
为什么你会把 `254` 和 `-2` 混在一起？因为你脑子里同时装了两件正确的事，但把它们叠在同一个符号上了：
- **同一个 8 位二进制字节 `1111 1110`（十六进制 `0xFE`）放在内存里**：
  1. 如果你用 **`uint8_t`（无符号 8 位，`0 ~ 255`）** 的眼镜去看它：所有 8 位都是数值位，$128+64+32+16+8+4+2+0 = \mathbf{254}$。
  2. 如果你用 **`int8_t`（有符号 8 位，`-128 ~ 127`）** 的眼镜去看它：最高位是 `1` 说明它是负数。怎么算它是负几？按你写的口诀**“取反（`0000 0001`）再加 1（`0000 0010` = 2）”**，所以它代表 **`-2`**！（或者用圆环记忆法：$254 - 256 = -2$）。
  3. 至于 **`-254`**：因为它超出了 8 位有符号数的下限 `-128`，所以 1 个字节根本装不下 `-254`，必须用 16 位 `int16_t`（`1111 1111 0000 0010`，即 `0xFF02`）才能装下 `-254`！

### 🔍 重点核查 E04：有符号与无符号混算的“隐式变号”陷阱

#### 1. 深入剖析与大白话讲解
结合刚刚讲的 E03：既然 `-1` 在内存里的补码是全 `1`（32 位下是 `0xFFFFFFFF`），当你在代码里把一个有符号的 `int` 和一个无符号的 `unsigned int`（或 `size_t`）放在一起比较大小或做减法时，**C 语言规定：有符号数必须先换上“无符号眼镜”，再和无符号数运算！**
于是，原本是负数的 `-1`，一戴上无符号眼镜，瞬间变成了 42 亿（`4294967295`）！

#### 2. 变式深化题（检验是否真懂）
> **变式题 E04-1**：下面这段倒序遍历数组的循环，是很多 C 程序员写图像处理时踩过的真实死循环 Bug：
> ```c
> size_t n = 10; // 注意 size_t 是无符号类型！
> for (size_t i = n - 1; i >= 0; i--) {
>     printf("%zu\n", i);
> }
> ```
> 请问：当 `i` 减到 `0` 打印完之后，再执行一次 `i--`，`i` 会变成 `-1` 然后结束循环吗？为什么这段代码会陷入无限死循环？应该怎么改？

**我的深化作答**：

<details><summary>💡 点击查看变式题解析</summary>

- **答案**：**不会结束，会无限死循环（并导致数组越界崩溃）**！
  因为 `i` 的类型是无符号的 `size_t`，无符号数**永远不可能小于 0**（`i >= 0` 恒成立）！当 `i = 0` 再执行 `i--` 时，它会下溢回绕成最大的无符号整数 `0xFFFFFFFFFFFFFFFF`，继续满足 `i >= 0`。
- **正确改法**：需要倒序减到 `< 0` 停止的循环下标，要么显式使用有符号整数（如 `for (int i = (int)n - 1; i >= 0; i--)`），要么用 `for (size_t i = n; i-- > 0; )`。
</details>
