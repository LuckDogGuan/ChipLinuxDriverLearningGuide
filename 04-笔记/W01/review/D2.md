### 2. 【有符号数与无符号数混算陷阱】
你在笔记第 120 行专门提醒：“**有符号数和无符号数混合运算，经常会出现结果不符合直觉的情况**”。
假设在相机采图程序里，你写了下面两行代码来判断剩余空间偏移：
```c
int offset = -5;
unsigned int header_size = 10;
```
当程序判断 `if (offset < header_size)` 时，结果是真还是假？为什么？
- **A.** 真，因为 `-5` 小于 `10`
- **B.** 假，因为 `int` 和 `unsigned int` 比较时，`offset (-5)` 会被自动转换成无符号大整数（`4294967291`），反而比 `10` 大
- **C.** 假，因为无符号数会自动变成负数
- **D.** 编译器禁止比较

**我的作答**：

<details><summary>💡 点击查看答案与解析</summary>

- **正确答案**：**B**
- **解析**：C 语言中当 `int` 与 `unsigned int` 同一表达式运算或比较时，有符号的 `int` 会隐式提升为 `unsigned int`。`-5` 的 32 位补码（`0xFFFFFFFB`）当成无符号数看就是 `4294967291`，导致 `offset < header_size` 为假！这也是为什么数组下标、缓冲区长度和偏移量混用 `int` 与 `size_t / uint32_t` 时要格外小心。
</details>

### 3. 【`sizeof` 与 `<stdint.h>` 固定宽度类型】

请问在标准 Linux / Windows 平台上，`CHAR_BIT` 和 `sizeof(uint32_t)` 输出的值分别是多少？格式符 `%zu` 匹配的是什么类型？
- **A.** `CHAR_BIT = 1`，`sizeof(uint32_t) = 32`，`%zu` 匹配 `uint32_t`
- **B.** `CHAR_BIT = 8`，`sizeof(uint32_t) = 4`，`%zu` 匹配 `size_t`
- **C.** `CHAR_BIT = 8`，`sizeof(uint32_t) = 8`，`%zu` 匹配 `long`
- **D.** `CHAR_BIT = 4`，`sizeof(uint32_t) = 4`，`%zu` 匹配 `int`

**我的作答**：

<details><summary>💡 点击查看答案与解析</summary>

- **正确答案**：**B**
- **解析**：`CHAR_BIT` 表示 1 个字节（`char`）包含多少个二进制位（bit），标准平台为 **8**；`uint32_t` 是精确的 32 位无符号整数，占 $32 / 8 = 4$ 字节；`sizeof` 运算符返回的类型是 `size_t`，在 `printf` 中对应的标准格式符正是 `%zu`。
</details>

### 4. 【八进制与十六进制字面量】
你在 D2 笔记末尾写了十进制 `254` 的转换：`254 -》B 11111110 -> 0 376 -> 0x FE`。
如果在 C 语言里写 `int a = 0376; int b = 0xFE;`，请问 `a == b` 是否成立？如果有人想写十进制的 `37`，为了代码对齐写成了 `int c = 037;`，`c` 实际的十进制值会变成多少？
- **A.** `a == b` 成立（都是 254）；`037` 会被当成八进制，实际十进制值变成了 `31`（$3\times 8 + 7$）
- **B.** `a == b` 不成立；`037` 依然是十进制的 `37`
- **C.** `a == b` 成立；`037` 会编译报错
- **D.** C 语言不支持八进制

**我的作答**：

<details><summary>💡 点击查看答案与解析</summary>

- **正确答案**：**A**
- **解析**：你在笔记第 209–210 行特别注明了“**0 开头是 8 进制，0x 是 16 进制**”。所以在 C 代码里数字前面随便加前导 `0`（比如把 `37` 写成 `037`）是个隐藏很深的 Bug，编译器会按八进制算出 $3\times 8 + 7 = 31$！
</details>

### 5. 【笔记找茬：检查你 D2 笔记第 113 行的补码例子】
你在 `note.md` 第 110–116 行写了一个 8 位二进制补码的例子：
```c
 -254 -> 1111 1110
// 取反
 |-254| -> 0000 0001 +1 -> 0000 0010
```
请对照你自己在笔记第 69–71 行《整型基础类型总表》里写的 **8 位有符号 `signed char`（`-128 ~ 127`）** 和 **8 位无符号 `unsigned char`（`0 ~ 255`）**：
1. 为什么 8 位二进制 `1111 1110` 不能表示有符号的 `-254`？（`1111 1110` 在什么类型下才是 `254`？）
2. 既然你算出 `1111 1110` 取反加 1 后的绝对值是 `0000 0010`（十进制的 `2`），那 `1111 1110` 作为 8 位有符号数（`int8_t`）时，它真正代表的负数是几？

**我的作答**：
1. 
2. 

<details><summary>💡 点击查看答案与解析</summary>

- **答案要点**：
  1. 因为 8 位有符号数（`int8_t` / `signed char`）最高位是符号位，只能表示 **`-128 ~ 127`**，根本装不下 `-254`（要存 `-254` 至少需要 16 位 `int16_t`）。`1111 1110` 只有在当成 **8 位无符号数（`uint8_t`）** 时，才是正数 **`+254`**。
  2. `1111 1110` 当成 8 位有符号补码时，真正代表的负数是 **`-2`**！（因为最高位是 `1` 表示负数，取反 `0000 0001` 加 `1` 得到 `0000 0010 = 2`，所以它是 `-2`）。你可以顺手把 `note.md` 第 113 行的 `-254` 改成 `-2（无符号下为 254）`，这样前后就完全自洽了！
</details>
