## 阶段 A　C 与 Linux 用户态

**A1.** `char *p[4]` 和 `char (*p)[4]` 有什么区别？`p + 1` 各移动多少字节（32 位系统）？
<details><summary>答案要点</summary>

前者是**指针数组**：4 个 `char*` 元素，`p+1` 指向下一个元素，移动 4 字节（一个指针大小）。
后者是**数组指针**：指向"含 4 个 char 的数组"，`p+1` 跳过整个数组，移动 4 字节（4×1）。两者移动字节数碰巧相同，但含义不同；换成 `int (*p)[4]` 就是 16 字节。
</details>

**A2.** 写出：把 `reg` 的第 n 位置 1、清 0、翻转；取出 bit[7:4] 字段。
<details><summary>答案要点</summary>

`reg |= 1u << n;`　`reg &= ~(1u << n);`　`reg ^= 1u << n;`　`(reg >> 4) & 0xF`
注意用无符号数 `1u`，避免对有符号数移位到符号位。
</details>

**A3.** `container_of(ptr, type, member)` 是怎么从成员指针推出外层结构体的？
<details><summary>答案要点</summary>

`(type *)((char *)ptr - offsetof(type, member))`：成员地址减去该成员在结构体里的偏移，就是结构体起始地址。转成 `char*` 是为了按字节做减法。
</details>

**A4.** 为什么 `sizeof(struct)` 常常大于各成员大小之和？
<details><summary>答案要点</summary>

编译器为满足对齐要求在成员之间和末尾插入填充字节。所以不能直接把结构体当成跨平台协议格式，位域布局同理。
</details>

**A5.** 文件描述符本质是什么？`fork` 之后父子进程对同一个 fd 共享什么？
<details><summary>答案要点</summary>

fd 是进程"文件描述符表"的下标，指向内核里的"打开文件表项"。fork 后子进程复制了描述符表，但指向**同一个打开文件表项**，所以共享文件偏移量和状态标志。
</details>

**A6.** 条件变量为什么要和互斥量一起用？等待时为什么写 `while` 而不是 `if`？
<details><summary>答案要点</summary>

检查条件和进入等待必须是原子的，否则可能丢失唤醒；`pthread_cond_wait` 会原子地释放锁并睡眠，醒来后重新加锁。用 `while` 是因为可能出现虚假唤醒，或者醒来时条件已被别的线程改掉。
</details>

**A7.** `select` / `poll` / `epoll` 各适合什么场景？
<details><summary>答案要点</summary>

select 有 fd 数量上限（常见 1024），每次要重设集合；poll 没有数量上限，但每次都要线性扫描全部 fd；epoll 先注册再等待，只返回就绪的 fd，适合大量连接。少量 fd（例如几个串口或设备）用 poll 就够了。
</details>

**A8.** AddressSanitizer 能抓到哪几类错误？
<details><summary>答案要点</summary>

堆、栈、全局变量越界；use-after-free；double free；配合 LeakSanitizer 还能报内存泄漏。编译参数 `-fsanitize=address -g -fno-omit-frame-pointer`。
</details>

**A9.** 静态库和动态库有什么区别？`ldd` 和 `nm` 分别看什么？
<details><summary>答案要点</summary>

静态库 `.a` 在链接时被拷进可执行文件；动态库 `.so` 在运行时由动态链接器加载，可以多个程序共享。`ldd` 列出程序依赖的动态库；`nm` 列出目标文件或库的符号表。
</details>

## 阶段 B　BSP 与驱动

**B1.** i.MX6ULL 的启动链路是怎样的？怎么从串口日志判断启动停在哪一步？
<details><summary>答案要点</summary>

ROM（片内固化代码，按启动引脚选启动介质）→ U-Boot（初始化 DDR、加载内核和 DTB）→ Kernel（`Starting kernel ...` 之后打印内核日志）→ init / rootfs（挂载根文件系统，启动第一个用户进程）。看最后一行日志属于哪个阶段的打印就知道停在哪。
</details>

**B2.** `insmod` 报 `invalid module format`，先查什么？
<details><summary>答案要点</summary>

`uname -r` 与 `modinfo xxx.ko` 里的 `vermagic` 是否一致；编译用的内核源码和配置是否就是板子正在运行的那一份；`dmesg` 里的具体报错。解决办法是用匹配的源码重新编译，不要强制加载。
</details>

**B3.** 注册一个字符设备的典型步骤是什么？卸载按什么顺序？
<details><summary>答案要点</summary>

`alloc_chrdev_region` 申请设备号 → `cdev_init` + `cdev_add` → `class_create` + `device_create` 自动生成 `/dev` 节点。卸载**逆序**：`device_destroy` → `class_destroy` → `cdev_del` → `unregister_chrdev_region`。错误路径也按逆序回滚。
</details>

**B4.** `copy_to_user` 的返回值是什么意思？
<details><summary>答案要点</summary>

返回**没有拷贝成功的字节数**，0 表示全部成功。不为 0 时驱动通常返回 `-EFAULT`。
</details>

**B5.** 用设备树时，platform 设备和驱动是怎么匹配上的？
<details><summary>答案要点</summary>

设备树节点的 `compatible` 字符串与驱动 `of_match_table` 里的条目比较，匹配成功后内核调用驱动的 `probe`，驱动在 probe 里读取节点属性、申请资源。
</details>

**B6.** 中断处理函数里哪些事不能做？耗时的工作放到哪里？
<details><summary>答案要点</summary>

不能睡眠：不能用 `mutex_lock`、`msleep`、`copy_to_user`、`kmalloc(GFP_KERNEL)` 等可能睡眠的操作。耗时工作放进 workqueue 或 threaded IRQ（tasklet 是旧用法）。
</details>

**B7.** 画出用 I2C 读器件某个寄存器的一次完整传输。
<details><summary>答案要点</summary>

START → 7 位地址 + W → ACK → 寄存器地址 → ACK → **Repeated START** → 7 位地址 + R → ACK → 数据 → 主机 NACK → STOP。地址没有 ACK（即 NACK）时，先查地址、上拉电阻、引脚复用和供电。
</details>

**B8.** SPI 的 CPOL / CPHA 是什么？UART 115200 波特率下一个比特约多长？
<details><summary>答案要点</summary>

CPOL 是时钟空闲电平（0 低 1 高）；CPHA 决定在第一个还是第二个时钟边沿采样。四种组合就是 SPI mode 0–3。
115200 波特率下一个比特 = 1 / 115200 ≈ 8.68 µs，8N1 一个字节含起始位和停止位共 10 位，约 86.8 µs。
</details>

**B9.** 为什么别的板子的 DTS 不能直接照搬？
<details><summary>答案要点</summary>

引脚复用、外设连接、GPIO 编号、电压和时钟配置都与具体原理图有关；照搬可能导致外设不工作，甚至引脚冲突。改之前先对照自己板子的原理图和运行时 `/proc/device-tree`。
</details>

## 阶段 C　摄像头数据通路

**C1.** RTSP 和 V4L2 有什么区别？
<details><summary>答案要点</summary>

RTSP 是网络流媒体协议（板子编码后通过网络推流）；V4L2 是 Linux 内核的视频采集接口（应用通过 `/dev/videoX` 拿帧）。RTSP 不是 V4L2 设备。
</details>

**C2.** 写出 V4L2 mmap 流式采集的调用顺序。
<details><summary>答案要点</summary>

`open` → `VIDIOC_QUERYCAP` → `VIDIOC_S_FMT` → `VIDIOC_REQBUFS` → 每个缓冲 `VIDIOC_QUERYBUF` + `mmap` + `VIDIOC_QBUF` → `VIDIOC_STREAMON` → 循环 `DQBUF` 处理再 `QBUF` → `VIDIOC_STREAMOFF` → `munmap` → `close`。
</details>

**C3.** 一帧 1280×1080 的 8 位灰度图有多少字节？换成 YUYV 和 NV12 呢？
<details><summary>答案要点</summary>

灰度 8 位：1280×1080×1 = 1,382,400 字节；YUYV 每像素 2 字节：2,764,800；NV12 每像素 1.5 字节：2,073,600。MJPEG 是压缩帧，长度不固定。实际还要看驱动返回的 `bytesperline`（stride）。
</details>

**C4.** 为什么不能用 `CAP_PROP_FPS` 当真实帧率？
<details><summary>答案要点</summary>

它通常是流或设备声明的标称值，不是实测值。真实帧率要用收到的帧数除以单调时钟（`steady_clock` / `CLOCK_MONOTONIC`）测出的时间。
</details>

**C5.** 标称帧率、SDK 输出帧率、PC 解码帧率、显示帧率有什么不同？
<details><summary>答案要点</summary>

分别对应传感器规格、板端编码输出、PC 端解码能力、界面刷新，任一环节都可能成为瓶颈。定位卡顿时要分段测，不能只看一个数。
</details>

**C6.** 生产者比消费者快、有界队列满了怎么办？
<details><summary>答案要点</summary>

三种策略：丢最旧（实时预览常用）、丢最新、阻塞生产者（会拖慢采集）。不管用哪种，都要**计数丢帧**，并观察内存不再增长。
</details>

## 阶段 D　AArch64 与 PCI/DMA

**D1.** EL0–EL3 各自通常运行什么？
<details><summary>答案要点</summary>

EL0 用户程序；EL1 操作系统内核；EL2 虚拟机监控器（Hypervisor）；EL3 安全监控（Secure Monitor / 固件，如 TF-A）。
</details>

**D2.** `ESR_EL1` 里怎么看异常类别？`svc #0` 和未定义指令分别是什么 EC？
<details><summary>答案要点</summary>

EC 字段在 bit[31:26]，取值用 `(esr >> 26) & 0x3F`。AArch64 下执行 SVC 的 EC = `0x15`；未知原因（如未定义指令）EC = `0x00`。最终以 Arm 架构手册为准。
</details>

**D3.** `ELR_EL1` 和 `SPSR_EL1` 分别保存什么？
<details><summary>答案要点</summary>

`ELR_EL1` 是异常返回地址；`SPSR_EL1` 是异常发生时保存的处理器状态（PSTATE）。`eret` 用这两个寄存器返回。
</details>

**D4.** 裸机程序里启动汇编和链接脚本分别做了什么？
<details><summary>答案要点</summary>

链接脚本决定代码和数据放在什么地址（QEMU virt 的 RAM 起始地址）、各段顺序，并导出 bss、栈等符号；启动汇编设置栈指针、清零 bss，然后跳转到 C 的 `main`。
</details>

**D5.** PCI 驱动 probe 的标准顺序是什么？remove 呢？
<details><summary>答案要点</summary>

`pci_enable_device` → `pci_request_regions` → `pci_iomap`（→ 设置 DMA mask → 申请中断）。remove 和错误路径**逆序**释放：`free_irq` / `pci_free_irq_vectors` → `pci_iounmap` → `pci_release_regions` → `pci_disable_device`。
</details>

**D6.** 访问 MMIO 为什么要用 `readl` / `writel`，不能直接解引用指针？
<details><summary>答案要点</summary>

`readl/writel` 保证按正确宽度访问、处理字节序，并带有必要的内存屏障，防止编译器优化掉或重排访问；`__iomem` 指针本身也不保证能直接解引用，在不同架构上的行为不同。
</details>

**D7.** coherent DMA 和 streaming DMA 有什么区别？
<details><summary>答案要点</summary>

coherent（`dma_alloc_coherent`）：CPU 和设备看到的数据始终一致，适合长期共享的控制结构。streaming（`dma_map_single` 等）：一次传输前映射、传完解除映射，所有权在 CPU 和设备之间交接，必要时需要 sync。
</details>

**D8.** EDU 设备默认只支持 28 位 DMA 地址，这意味着什么？
<details><summary>答案要点</summary>

设备只能访问 0–256 MB（2^28）范围内的地址，驱动要调用 `dma_set_mask_and_coherent(dev, DMA_BIT_MASK(28))`，让内核分配或映射出设备够得着的地址。mask 设错时，DMA 可能失败或访问错地址。
</details>

**D9.** INTx 和 MSI 有什么区别？为什么必须按设备的规定确认中断？
<details><summary>答案要点</summary>

INTx 是共享的电平中断线；MSI 是设备向特定地址写一条消息来触发中断，不共享。不确认（EDU 要写 `0x64` 清除）的话，电平一直保持，中断会反复触发，形成中断风暴，内核可能禁用这条中断线。
</details>

## 阶段 E　调试与交付

**E1.** 自旋锁和互斥锁怎么选？
<details><summary>答案要点</summary>

自旋锁持有期间不能睡眠，适合临界区很短或在中断上下文中使用（与中断共享数据时用 `spin_lock_irqsave`）；互斥锁可以睡眠，只能在进程上下文中使用，适合较长的临界区。
</details>

**E2.** lockdep 和 KCSAN 各查什么问题？
<details><summary>答案要点</summary>

lockdep 查**锁的误用**：加锁顺序可能死锁、在错误的上下文中用锁等。KCSAN 查**数据竞争**：没有同步保护的并发访问。目标不同，可以互补。
</details>

**E3.** ftrace 的 `function_graph` 能帮你看什么？
<details><summary>答案要点</summary>

内核函数的调用关系和每个函数的耗时，适合看一个操作（例如一次 DMA 或一次 ioctl）在内核里走了哪些路径、慢在哪里。
</details>

**E4.** 吞吐、延迟、CPU 占用有什么区别？写性能报告时要记录什么？
<details><summary>答案要点</summary>

吞吐是单位时间完成量；延迟是单次操作耗时；CPU 占用是消耗的计算资源。三者不能互相替代。报告要写：工具版本、测试场景、完整命令、原始输出、解释和限制。
</details>

**E5.** 用 C++ 的 RAII 包装 C API（例如 `open/close`）有什么好处？
<details><summary>答案要点</summary>

资源在构造时获取、析构时自动释放，异常或提前 return 都不会泄漏，错误路径不用再手写一堆清理代码。配合 `unique_ptr` 自定义删除器也可以做到。
</details>

**E6.** 一份合格的故障定位报告包含哪些部分？
<details><summary>答案要点</summary>

现象 → 复现步骤 → 证据 → 至少 2 个假设 → 验证方法与结果 → 根因 → 修复与回归验证。模板见 [故障定位报告模板](../07-模板/故障定位报告模板.md)。
</details>
