# 使用规则（标签 / 时间 / 笔记 / 五道门 / 设备分工）
> 来源：原手册第 0 节。开始学习前先读一遍。

### 标签

| 标签 | 含义 | 规则 |
|---|---|---|
| ✅ | 必学 | 当周优先完成 |
| 🔧 | 动手必做 | 必须留下证据（日志、截图、波形、代码） |
| ⏩ | 你已有基础，可快进 | 先做自测，通过就 1.5–2 倍速或直接跳 |
| ⭐ | 选读 | 不计验收，看不完没关系，不能挤占 ✅ 和 🔧 |
| 🟡 | 条件必学 | 只有实际技术问题需要、前置基础具备或硬件到位才升级 |
| 📝 | 笔记与证据 | 与代码放同一仓库 |

### 每周时间（给笔记留足空间）

| 日 | 内容 | 上限 |
|---|---|---|
| D1–D4 | 视频/阅读 ≤60′ + 动手 ≤30′ + **笔记 15′** | 约 100′ |
| D5 | 选读或机动，没落后就休息 | ≤45′ |
| D6 | 周实验 + **周报 30′** | ≤150′ |
| D7 | 休息，不安排 | 0 |

- 正常周约 9–10 小时；**轻量周**（W05、W10、W15、W20、W25、W32、W40）≤6 小时，用来补课、整理笔记、做展示。
- 日子可以顺延，顺序不变；老板临时有事就往后挪，不通宵追。
- **最低版本**（一周只有 5 小时）：只做 D1–D3 + D6 的最小实验，D4、D5 全部顺延。
- 当周核心实验没跑通，可以交"可复现的阻塞日志 + 下一步验证清单"，下个小阶段继续。

### 笔记规则

- 每天 3 行：①今天学了什么（一句话）②一个没弄懂的点 ③一个能验证的小结论（代码片段/截图/波形）。
- 每周一个证据包（放进 Git）：

```
04-笔记/Wxx/
  note.md       # 每日 3 行 + 本周总结
  code/         # 本周实验
  evidence/     # 截图、波形、日志、原理图标注
  report.md     # 周报
```

- **周报 5 项**：目标 / 做了什么 / 证据 / 遇到的问题与定位过程 / 下周只做一件事。

### 每个阶段末用五道门自测

功能能跑 / 能讲清机制 / 能独立重写关键部分 / 能复现并定位一个故障 / 别人按 README 能复现。

### 设备分工（不要混用）

| 设备 | 用途 | 注意 |
|---|---|---|
| 野火 i.MX6ULL Pro | ARMv7 Linux、交叉编译、内核/设备树/驱动 | 32 位 Cortex-A7，不是 AArch64 板 |
| Luckfox Pico Zero + ISG1321 | MIPI CSI 采集、RTSP、V4L2 原始帧 | 见第 4 节；ISG1321 是**黑白**全局快门相机 |
| PC（Ubuntu 虚拟机/WSL2） | C/C++、GDB、CMake、OpenCV、QEMU | WSL2 下 USB 设备与 KVM 受限 |
| QEMU | AArch64 裸机、x86_64 的 PCI EDU 设备 | 只是软件模型，不等于真实 PCIe 链路调试 |

### 现行优先级（2026-11-17）

每周可视化≤15 分钟作为引导；原始手册/官方源码为依据；调试与根因分析是约 70% 的实践重心（不是机械学时配比）。不因为近期求职而限制芯片深度。详见 [修订路线](新版路线与删减依据.md) 和 [故障定位方法](../05-学习校验/调试能力贯穿40周.md)。
